# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Python 3.11+, mostly standard library (`requirements.txt` only adds Pillow). Run everything from the repo root, because modules import as `core.*` / `pipeline.*`.

```bash
python3 server.py                                  # local site + JSON API on :8000 (PORT env overrides; if busy it takes the next free port up to +19)
python3 -m unittest discover tests                 # full test suite
python3 -m unittest tests.test_foryou              # one test module
python3 -m unittest tests.test_foryou.TestName.test_method   # one test
python3 run_daily.py --dry-run --skip-audio        # full daily pipeline, no LLM/TTS calls
python3 -m pipeline.render_html                    # re-render static pages from brief.sqlite3
python3 -m pipeline.ingest_llm --url <url> --add-to-issue --rebuild   # ingest one story into today's issue
python3 -m pipeline.ingest_seed && python3 -m pipeline.build_issue && python3 -m pipeline.render_html  # cold-start seed
python3 -m pipeline.resolve_predictions due                                   # live forecasts past their date
python3 -m pipeline.resolve_predictions resolve <id> --status correct|wrong|void --evidence <url> --by "<name>" [--note "..."]
python3 -m pipeline.resolve_predictions draft <id> --evidence <url>          # LLM-suggested verdict; records nothing
python3 -m pipeline.tune_scoring [--apply]                                    # weights vs resolved outcomes (needs 20)
python3 -m core.cluster_eval                                                  # clustering precision/recall on the gold set
python3 -m pipeline.email_edition                                             # public/email/<date>.html + .txt
python3 -m pipeline.experiment_report                                         # For You A/B variants: satisfaction + 7-day return
python3 -m pipeline.personal_digest [--all]                                   # per-reader Your 5 into outbox/ at their delivery hour
./pith [developer|founder|investor|everyday]                                  # print the latest issue in the terminal (core/cli_format.py)
```

Video (Remotion, in `video/`): `npm start` (preview), `npm run build` (renders `out/pith-brief.mp4`).

There is no linter or formatter configured. CI runs Python **3.11** (`.github/workflows/*.yml`) while local machines may be newer, so avoid 3.12+ f-string syntax (backslashes or the outer quote character inside `{…}`).

- `.claude/launch.json` defines the `pith-dev` preview server (port 8010, `PITH_REFRESH_MINUTES=600`). Every page except About needs a login: create a username account on the About page's sign-in card (there is no guest pass); it sends you on to `?next=` or Daily News. The Google/GitHub/X/LinkedIn buttons stay greyed out until their OAuth keys are set.
- If feeds all fail locally with `CERTIFICATE_VERIFY_FAILED`, the Python install lacks CA certificates (macOS python.org builds need "Install Certificates.command"); the server then falls back to `core/demo_news.py`. It is not a code bug.
- To try the daily pipeline without touching committed files, call `run_daily_pipeline(dry_run=True, skip_audio=True, db_path=<copy of brief.sqlite3>, output_dir=<temp dir>)` from `pipeline/orchestrate_daily.py`; `run_daily.py` itself writes to `brief.sqlite3` and `public/`.

## Architecture

The site has two halves that share a server and front-end shell but use **separate SQLite databases**:

1. **Daily Brief** (`brief.sqlite3`): an LLM-drafted daily issue of 5 cards plus "Safely Ignore Today", each card carrying a falsifiable prediction.
   - Flow (`pipeline/orchestrate_daily.py`, entry `run_daily.py`): `core/sources.py` collects candidates → `pipeline/ingest_llm.py` asks the LLM (`core/llm.py`, prompts in `core/prompts.py`) for 0–100 factor ratings plus a card draft → `core/scoring.py` takes the weighted sum, subtracts penalties, and applies the threshold (60, or 78 for "High") → `core/verification.py` drops any claim whose `quoted_span` isn't a substring of the fetched source text → `core/db.py` stores the issue → `pipeline/build_issue.py` writes `feed.json`/`rss.xml` → `pipeline/render_html.py` writes the HTML → `pipeline/audio_brief.py` makes ElevenLabs audio in `public/audio/`.
   - LLM provider is picked by `--provider` / `PITH_LLM_PROVIDER` (gemini, openai, anthropic, ollama, simulated). `auto` picks the first provider with a key set (Gemini, then OpenAI/Groq, then Anthropic) and uses the simulated provider only when none is set; `--dry-run` always uses the simulated provider, so the pipeline runs without API keys.
   - `schemas/card.schema.json` and `issue.schema.json` are documentation only: no code validates against them. Validation lives in `Card.validate()` / `Prediction.validate()` (`core/models.py`) and `core/verification.py`.
   - `core/scoring.py` loads `scoring_weights.json` (written by `pipeline/tune_scoring.py`) if present and valid, else `DEFAULT_WEIGHTS`. Tune only on forecast outcomes, never on clicks/saves.
   - `core/llm.py` providers use raw HTTP (stdlib only). The Anthropic one defaults to `claude-opus-5-5`, sends no sampling params, joins only `text` blocks (responses start with thinking blocks) and uses `fallbacks: "default"`.
   - `pipeline/build_issue.py` also writes the email edition (`pipeline/email_edition.py`); set `PITH_SITE_URL` to change links.
   - `core/ledger.py` computes Brier score, hit rate and Brier skill score over resolved **live** predictions only.
   - **Ledger integrity rules (do not weaken):** predictions have `provenance` `live` or `illustrative`; illustrative ones (hand-written examples, e.g. `hist-pred-*`) are never counted in any score. Resolutions go only through `Database.record_resolution` (named reviewer, evidence for correct/wrong) into the append-only `prediction_resolutions` table; triggers block UPDATE/DELETE there and block edits to forecast fields after the publication day. Never write `status` on `predictions` directly, never use `INSERT OR REPLACE` on `predictions`, and never fabricate a forecast, track-record number or crowd figure in a renderer.
   - Schema changes for `brief.sqlite3` are appended to `Database.MIGRATIONS` (numbered, tracked in `schema_version`); never edit a shipped migration. `Database(path)` applies pending migrations on construction, so merely opening the committed DB (the server, `BRIEF`, some tests) modifies it.
   - Accepted cards beyond the top 5 are stored as the issue's `pool` (`DailyIssue.pool`, max `POOL_MAX`). Their forecasts are `live` and count in the Ledger, so the pool must stay published (the "More verified shifts" section in `render_html.py`, `/api/issue`, `feed.json`). The number of candidates, and so LLM calls per run, is capped by `PITH_MAX_CANDIDATES` (default 30) in `core/sources.py`.
2. **For You** (`foryou.sqlite3`, schema in `core/newsfeed.py`): a general-news personalized feed.
   - `core/newsfeed.py` pulls about 40 RSS feeds (`FEED_REGISTRY`; optional `region` feeds `FEED_REGIONS` for the region preference). `server.py` runs it in a daemon thread every `PITH_REFRESH_MINUTES`. When offline it seeds `core/demo_news.py`.
   - `core/clustering.py` merges multi-outlet coverage. Its `MATCH_THRESHOLD` is calibrated on `tests/fixtures/cluster_gold.json`; run `python3 -m core.cluster_eval` before changing matching, and keep precision ≥ 0.95.
   - `core/textfeatures.py` turns each article into rule-based topics, TF-IDF keywords, capitalized-phrase entities, and its publisher. It deliberately uses no ML models.
   - `core/recommender.py` learns per-user affinities from events (half-life decay) and ranks by `confidence*personal + (1-confidence)*baseline`, then applies an MMR re-rank, Thompson-sampling exploration slots, and a per-item explanation. The `CORPUS` singleton caches features in memory and reloads when the article count or latest fetch time changes.
   - `core/auth.py`: PBKDF2 passwords, session token in an HttpOnly cookie, with only the token's SHA-256 stored.
   - `core/oauth.py`: sign in with Google, GitHub, X, LinkedIn (authorization code; PKCE for Google and X; hashed single-use `state` bound to a cookie; `safe_next` blocks open redirects). No email is requested and no access token is stored. Identities live in `user_identities`; OAuth-only accounts have a non-PBKDF2 `password_hash`, so password login is impossible for them. Accounts are never merged by email: a signed-in reader connects more providers with `?link=1`. `oauth.HTTP` is swapped for a fake in tests.
   - `core/social_signals.py`: turns the profile read at sign-in (GitHub repos/stars/bio, X bio/follows, Google/LinkedIn locale country) into topic/keyword/entity affinities plus an optional region. `sync` stores what it applied and applies only the difference next time (idempotent); `forget` subtracts it. Region is only set when the reader hasn't chosen one. Readers see and remove imports in the Taste DNA "Connected accounts" panel.
   - `core/brief_bridge.py` featurises the last 3 issues' brief cards into the article shape, so `Recommender.lookup()` finds cards too and feedback on a card trains the same profile.
   - `core/your5.py` picks a personal "Your 5" from today's 5 core cards, the issue's `pool` (extra cards that passed the same threshold and verification, `cards.tier='pool'`, migration 4) and recent unread cards. Slot 1 is always today's top core card ("must-know"); the rest are editorial score + affinity match + follows, with an MMR diversity penalty. Role inference matches whole stemmed tokens.
   - Learning rules in `Recommender.record`: only `ALLOWED_KINDS` are logged; `clear_worth` undoes a "worth my time" rating (switching it off is neutral, never a negative); dwell is judged against the reader's own median once they have 5 reads.
   - Also on the For You side: `core/follows.py` (entity / phrase / story follows; story updates reuse the clustering similarity), `core/prefs.py` (depth, region, delivery hour, tz; depth is inferred from dwell until chosen), `core/userfeeds.py` (reader-added RSS: SSRF-checked fetches that connect only to the address they checked, no env proxy, articles with `feed_id` `u-…` only reach subscribers and never Trending), `core/experiments.py` (deterministic A/B assignment + exposure log), `core/personal_forecasts.py` (a reader's calls vs Pith: live forecasts only, calls count only within 3 days of publication and before resolution, implied probability = Pith's ±15 points), `core/personal_audio.py` (the spoken brief as chapters: intro, each story, followed-story updates, forecast calls, sign-off; length follows depth, about 45s / 90s / 3 min; `personal_brief()` is shared by the server and `pipeline/personal_digest.py`, which pre-records the studio MP3 at the reader's delivery hour when `ELEVENLABS_API_KEY` is set; MP3s go to gitignored `private_audio/`).

`server.py` is a stdlib `SimpleHTTPRequestHandler` serving `public/`, with hand-routed APIs: `/api/issue`, `/api/ledger`, `/api/score`, and the For You routes (`/api/me|feed|profile|your5|your5/script|your5/audio|digest|events|onboard|onboard/pairs|follows|forecasts/me|forecasts/seen|prefs|feeds|auth/*|refresh`). POST bodies must be JSON; that content-type check is the CSRF guard, so keep it. Pretty paths (`/ledger`, `/foryou`, …) map to the `.html` files (`MEMBER_PAGES`). **Access is deny-by-default:** signed out, only `/about` (`ABOUT_PATHS`), its shell assets (`OPEN_ASSETS`), `/healthz`, `/api/me`, `/api/auth/*` and the OAuth routes answer; every other page redirects to `/about?next=<path>#access` and every other file or API (feed.json, rss.xml, email/, audio/, `/api/issue`, `/api/ledger`, `/api/votes`, `/api/score`, …) returns 401. The decision is made on `normalise_path()` (percent-decoded, dot segments collapsed, lower-cased) and open assets are served from their canonical path, so keep any new check on that path, and add to `OPEN_ASSETS` only files with no news content. HEAD goes through the same gate. `_serve_about` swaps `data-session="out"` (the default baked into `about.html`) to `"in"` for a signed-in reader; CSS hides `[data-members]` nav/footer links when it's `out`. Member responses are `Cache-Control: private, no-store`. Unexpected handler errors become a JSON 500 (`_guard`). Sign-in routes: `GET /api/auth/providers`, `GET /api/auth/oauth/<provider>/start|callback` (rate limited with login), `POST /api/connections` (`forget` / `disconnect`; the last way to sign in can't be disconnected). Sign-in and account creation live on the About page (`setupAboutAccess` in `app.js`); `foryou.js` sends a signed-out or expired session to `/about?next=%2Fforyou`. OAuth failures redirect to `/about?auth_error=` (or `/foryou?auth_error=` when a signed-in reader was connecting another account); `oauth.safe_next` defaults to `/` and accepts only printable-ASCII same-site paths. Reader forecast votes: `POST /api/vote` (login; refused unless the card has a live, open forecast whose date has not passed) and `GET /api/votes?card_id=` (`core/votes.py`, `forecast_votes` table). Login/signup, other POSTs and `/api/refresh` are rate limited per IP (`core/ratelimit.py`). `/healthz` returns `{"ok": true}`. Decommissioned paths (`/horizon`, `/bounty`, `/matrix`, `/economics`, `/terminal`) are handled explicitly.

### Generated vs hand-written front-end files

- **Generated, so edit the Python renderer instead:** `public/index.html`, `ledger.html`, `patterns.html` (`pipeline/render_html.py`), `archive.html` and `about.html` (`pipeline/render_extended.py`), and `feed.json`/`rss.xml`. The shared global nav lives in `render_extended.get_nav_html`.
- `style.css` is token-driven (light and dark sets on `:root[data-theme]`; legacy names like `--gilt`/`--red-ink` alias the accent so older inline markup still themes). Fonts (Newsreader, Inter, JetBrains Mono) and the pre-paint theme pick come from `render_extended.get_head_assets()`; `foryou.html` carries its own copy. Theme default follows the OS until the reader toggles it.
- **Hand-written:** `public/app.js` (brief UI, lens switching, Beat-the-Brief ELO, Web Audio sounds), `style.css`, `foryou.html`, `foryou.js`, `foryou.css`.

## Repo conventions

- `.github/workflows/daily_brief.yml` runs `run_daily.py` daily at 05:00 UTC. It **commits `brief.sqlite3` and `public/` back to the branch** (`chore(daily): ... [skip ci]`) and deploys only the front door to GitHub Pages (`about.html`, also as `index.html`, plus `style.css`, `app.js` and icons, staged in `_site/`): static hosting can't check a login, so member pages are served only by `server.py`. Note the repo is public, so the committed `public/` files are readable on GitHub regardless. Expect bot commits on `main`, and pull before editing generated files.
- `brief.sqlite3` is committed, so before committing it make sure no running server still holds writes in `brief.sqlite3-wal` (stop it, or run `PRAGMA wal_checkpoint(TRUNCATE)`). Side files are gitignored.
- `.github/workflows/daily_video_pipeline.yml` runs the Whisper alignment (`pipeline/video_align.py`), the Remotion render, and `pipeline/auto_publish.py`. `auto_publish` defaults to `--dry-run`.
- OAuth: `PITH_GOOGLE_CLIENT_ID`/`_SECRET`, `PITH_GITHUB_…`, `PITH_X_…`, `PITH_LINKEDIN_…`, and `PITH_AUTH_BASE_URL` (the server's public origin; the redirect URI to register is `<base>/api/auth/oauth/<provider>/callback`). X's follows endpoint needs a paid API tier; without it only the bio is used.
- Env vars used: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` (+`OPENAI_BASE_URL`), `GEMINI_API_KEY`, `GROQ_API_KEY`, `ELEVENLABS_API_KEY`, `PITH_LLM_PROVIDER`, `PITH_REFRESH_MINUTES`, `PITH_MAX_CANDIDATES`, `PITH_SITE_URL`, `PITH_SECURE_COOKIES=1` (adds `Secure` to cookies), and the social publishing tokens (`YOUTUBE_API_TOKEN`, `X_API_KEY`, `LINKEDIN_ACCESS_TOKEN`).
- `PROJECT_CONTEXT.md` is the product chronicle. Update its phase table when adding or removing a destination.
- Tests are named by phase (`tests/test_stepN.py`). Newer ones build temp `foryou`/`brief` DBs (see `tests/test_step6.py`'s `Env`); reset the `CORPUS._sig` and `BRIEF._sig` caches in setUp/tearDown, since both singletons cache by database signature.
